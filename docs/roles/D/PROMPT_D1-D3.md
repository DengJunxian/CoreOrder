# CoreOrder 团队协作模式补充指令

本项目采用公共基线统一、成员独立研发、GitHub 分支隔离、组长集中集成的协作模式。

你当前只需要负责本人任务书规定的技术模块，不需要等待其他成员完成其全部工作，也不需要主动承担整个系统的集成工作。

请按照本人阶段提示词依次完成第1至第3阶段。

当其他成员的生产模块尚未交付时，优先使用公共技术契约、真实公共 fixture、明确的接口签名和独立测试 harness 开展研发。

测试替身只能用于模块级测试，不得冒充生产实现。

必须完成本人能够独立实现和验证的全部技术任务，包括源码研究、核心模块开发、模块级正确性测试、必要微基准、接口说明及研究记录。

对于确实依赖其他成员或完整系统集成的任务，将其明确标记为 INTEGRATION_PENDING，并提供准确的依赖说明、接口签名、接入示例和集成验收方法。

不得因为外部模块暂未交付而无限等待，也不得擅自重新实现其他成员负责的核心模块。

所有生产代码必须遵循 R4 公共技术契约。

请在本人独立 GitHub 分支内开展开发。按照实际授权提交并推送代码，不直接修改 main，不自行合并其他成员分支。

最终向组长交付：

1. 完整的个人技术模块。
2. 真实模块级测试与运行日志。
3. 清晰的代码与接口说明。
4. 实际 Git commit SHA。
5. 模块接入方法及依赖清单。
6. 已完成、未完成和待集成任务清单。
7. 本人研究记录和论文方法素材。

组长将在所有成员核心模块交付后，统一负责完整系统集成、跨模块联调与系统级验收。

正式端到端性能实验必须等待统一实验协议冻结，不得将独立微基准结果冒充正式系统性能结果。

完成前三阶段的独立研发及交付后停止，等待组长发出后续集成或正式实验任务。
