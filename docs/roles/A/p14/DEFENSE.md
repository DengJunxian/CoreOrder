## 技术问答

### 1. 为什么选择 PAMS？

固定源码中已有可逐行检查的 SequentialRunner、Market、FCN、订单簿、事件和账户更新，还有原样例能作为参考输入。选型使我们在同一个金融模型中改变局部执行机制，并让独立参考程序直接调用原市场。相同配置下若出现行为差异，可以追到具体顺序、价格或 RNG。 [原平台预印本](https://arxiv.org/abs/2309.10729) · [固定源码与样例](https://github.com/masanorihirano/pams/tree/6cd53810103780770c5b5d6ee0069ccab9f4b358)

### 2. 逐项压回为什么保留统一成交价？

原撮合先按最优买卖方扫描、在局部变量扣减剩余量、记录每对的订单引用和量，并取得最后一个能定价配对的价格。恢复发生在统一价和配对列表确定后。压回的是相同对象，后续逐对执行仍使用原统一价与原顺序。原市场的价格规则、成交量、事件和账本继续工作。 [原撮合实现](https://github.com/masanorihirano/pams/blob/6cd53810103780770c5b5d6ee0069ccab9f4b358/pams/market.py#L1083-L1199) · [局部改动](../../../../src/coreorder/market_adapter.py)

### 3. 堆数组的排列不同，如何保证下一笔没人插队？

堆约束要求每个父节点都优先于其子节点。固定 PAMS 的同侧合法订单按市价优先、限价方向、挂单时间和唯一 ID 排序，所以当前集合存在唯一最优根。两个合法堆上都弹出该订单，剩余集合相同，归纳得整个弹出序列相同。依赖内部数组、改变比较字段或放入缺失唯一 ID 的对象会破坏前提。比较器不变使撤单和过期仍按上游规则执行。 [原比较器](https://github.com/masanorihirano/pams/blob/6cd53810103780770c5b5d6ee0069ccab9f4b358/pams/order.py#L195-L239) · [定向核验](../../../gates/G1-heap.md)

### 4. 为什么批宽取剩余名额，空结果该怎么处理？

剩余名额为 `r` 时，前缀中的每位代理最多贡献一个非空列表。至多先调用 `r` 位，所以最后一位之前不会用尽名额并越界调用。空列表不消耗名额，按同一排列取下一段。该限额计的是代理列表，单个代理给两个市场产生两条订单仍占一格。回建后 PAMS 还会抽样排列这些列表，保留这一第二次排列同样重要。 [批次代码](../../../../src/coreorder/native_serial.py#L79-L128)

### 5. 设置相同 seed 为什么还需要核对 RNG 状态？

seed 只固定初态。访问了原版不会访问的代理、交换该代理的市场访问顺序，或漏掉 normal margin 在无订单分支的调用，都会改变样本对应的决策行或状态。CPython 的 Gaussian API 缓存一个样本，跳过一次调用即使没有新增交易，也可能改变后续输入。验证同时保留 runner 与代理状态、Gaussian 缓存及 NumPy 随机状态。 [上游 FCN](https://github.com/masanorihirano/pams/blob/6cd53810103780770c5b5d6ee0069ccab9f4b358/pams/agents/fcn_agent.py#L122-L252) · [E 的状态编码](../../../../validation/codec.py)

### 6. 怎样区分算法、Cache、原生化和多核收益？

H01 固定 py-seq，只比较恢复方式，比较次数支持算法工作量的解释。原生化应比较同一增量堆上的 py-seq 与 direct serial，多核应比较同一核和布局的 serial 与不同 worker。布局和局部性需要同公式、同工作量、同线程设置，并且报告硬件事件、作用域和有效采样。当前没有 PMU 回执，因此堆计数不能推成 miss 或带宽下降。 [G3 候选方案与状态](../../../gates/G3.md)

### 7. 为什么核很快，整轮市场仍可能没有收益？

可并行比例为 `f` 时，忽略额外代价的理想上界是 `1/((1-f)+f/p)`。原版排列、Gaussian、packing、订单实例化以及串行市场提交仍有成本，实际还需汇合。P11 在 W2-H 和 W3-START 观察到相同增量堆上的 native-serial 未进一步降时，W4 两 seed 方向不同。保留负结果有助于定位后续工作。 [Amdahl 论文](https://www.cs.cmu.edu/~18742/papers/Amdahl1967.pdf) · [P11 原始运行表](../evidence/P11-runs.csv)

### 8. 哪种情形会使增量恢复优势消失？

单侧原版线性建堆，增量的堆调整最坏为 `O(k log(n+1))`。当暂取订单接近整簿，或者堆本来就短时，算法的渐近上界允许排序反转，实际还受对象比较和列表扩容影响。P11 最高单条恢复比例约 53.5%，故统计保留分布及尾部。现有正式矩阵尚未执行，无法给出通用切换阈值。 [逐侧数据](../evidence/P13/figures/heap-mechanism-pilot.csv)

### 9. 当前能现场演示哪一项，验到什么程度？

同一两市场配置和 seed 42，用原版 PAMS 作 oracle，依次比较 py-seq 两堆模式、native-serial AoS 与两 worker 的 native-parallel SoA。展示 `PASS` 的结构范围，以及有序事件、步状态和 RNG 摘要。生产回执仍须通过正式门禁的输入身份和量测来源检查。现场演示使用已装好依赖的本机与一份新输出目录。 [复现命令与结果](REPRODUCE.md) · [G2 原始记录](../../../gates/G2.md)
