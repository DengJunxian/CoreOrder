## C｜持久 Taskflow、真实 range 和同步

**团队第 8–9 页，个人附页 5。** 我的执行器在一次运行内复用线程池。任务写入半开范围内互斥的输出槽，完成后按输入顺序消费，因此任务完成顺序不会改变交易提交。华硕 W2-H 生产记录是每批 256 行，grain 128 划出两个有效 range。32 批中有 14 批由同一线程执行两段，其余 18 批有两个执行线程。这是实际参与人数，不能由配置数推出，也不等于 CPU 利用率。

**团队第 10 页，个人附页 6。** 同一真实输入的 256 行单批，四 worker 回放为 0.116 倍；E05 合并至 8,192 行一次提交时为 1.629 倍。大点拼接了 32 个批次，所以调用与汇合的摊销条件变了。整机配对给出 W1-H 四 worker 的 0.947 倍及 23.7% 效率；W3 为 1.001 倍及 25.0%，区间跨过 1。C++ 能并行执行的部分取决于真实任务规模，市场的串行部分和语言边界一直保留。

## 技术问答库

### A｜算法、语义和研究范围

1. **为何选 PAMS？** 它提供完整真实市场、可运行的串行参考和可固定的版本。能把堆、执行器、布局这些变量与共享撮合语义分开。
2. **同 seed 为什么不够？** 调整一次订单或抽样顺序可以改变未来可访问行、成交及随机消耗。验收比较初态、有序事件、逐步状态、终态及 RNG。
3. **增量恢复保持什么不变量？** 剩余堆合法，待恢复对象和比较键确定，临时撮合扫描得到的待成交对及价格保持。重新入堆后逻辑出堆序列相同。
4. **时间复杂度怎样比较？** stock 全堆堆化为 \(O(n)\)，插回 \(k\) 个订单的比较上界为 \(O(k\log(\max(n,2)))\)。动态数组复制按摊销考虑，端到端时间还包括扫描与撮合。
5. **什么时候不一定获益？** 浅簿、较高恢复比例或非恢复阶段主导时，减少的比较工作可能很小。W0-H 的正式仿真加速为 1.251×，完整进程为 1.036×。
6. **安全前缀长度为何至多取剩余额度？** 每个已访问代理最多贡献一个非空列表。长度不超过剩余额度时，该前缀最后一位之前无法消费完额度。空结果使原流程继续访问，按同一光标补批。
7. **哪些市场进入验证范围？** 已验证的无费普通市场及精确的受支持代理类型。原生不支持配置显式拒绝，用户可在运行前选 py-seq。

### B｜浮点与绑定

8. **FCN 三项的含义是什么？** Fundamental 看基本价值，Chartist 看历史价格走势，Noise 使用随机扰动。两布局和两个执行路径调用共同标量公式。
9. **为何关闭 fast-math 和收缩？** 重排或合并可改变浮点舍入，从而影响下单方向、价格及后续轨迹。真实输出还受平台数学库影响，所以每个环境独立核验。
10. **Gaussian cache 如何处理？** 保留 Python 随机对象及原调用序列，结尾比较完整随机状态，含已缓存的高斯样本。
11. **GIL 在什么位置释放？** 查验 NumPy 缓冲和 owner、准备结果后，数值区间脱离 GIL。回到 Python 侧再使用 Python 对象并构造订单。
12. **非法数组怎样处理？** 绑定拒绝不匹配 dtype、字节序、布局、形状、stride 或对齐。可定位的错误行按确定顺序汇报。
13. **为什么增加 native-serial 对照？** direct 与 Python 在相同增量底座上比较语言和数据边界的净效应。direct 与 Taskflow 再比较执行器及调度变化。
14. **原生化为何会变慢？** 原业务仍需依次取随机数、整理真实输入和回建订单。小内核的本地节省可能被准备、绑定、分配和回填覆盖。华硕 E02 在 W1-H 和 W3 的直调仿真速度比为 0.860× 和 0.856×。

### C｜并行与调度

15. **持久池省下什么？** 线程创建和销毁按 run 摊销。每批任务提交、排队、执行和汇合仍发生。
16. **并行调度顺序如何不改变订单顺序？** 任务写互斥的输出范围，完成后由上层按原行序读出并提交，调度时间顺序不会成为订单顺序。
17. **为什么四 worker 经常只用到两个范围？** W2-H 实际 256 行、grain 128 时生产回调形成两个范围。线程参与度还由调度决定，T05 观察到 14/32 批由同一线程执行两个 range。
18. **任务数可否直接用 ceil 算？** 分块会受实际布局长度、调度策略和执行入口影响。本研究报告生产回调记录的实际 range 数、大小及参与线程数。
19. **如何解释 Taskflow 单 worker？** 保留调度器但不给跨 worker 并行机会，用它观察相对 direct 的净边界成本，范围包含同步与执行上下文差异。
20. **8,192 行的加速为何和真实市场不同？** replay 把真实 W2-H 的 32 个生产批次并进一次提交，减少调用和汇合频率，改变其摊销条件。
21. **Amdahl 可以怎样使用？** 先用明确边界识别可以加速的部分，固定其余阶段再作敏感性分析。含绑定、分配和等待的总区间不能当作纯计算比例。

### D｜布局、访存与硬件计数

22. **AoS/SoA 各有何访问特点？** AoS 集中一行多字段，SoA 连续存同一字段，适合列式或实际向量化访问。当前 FCN 读取多个字段，具体收益由编译和路径决定。
23. **两布局的数据量相同吗？** 对应数值字段名义输入均为 112 B/行，输出 16 B/行。生产 metadata、缓冲复用和 replay 的原始输入留存会改变存活总量。
24. **Cache line 64 B 对 AoS 意味什么？** 112 B 的记录跨越多个缓存行，实际覆盖取决于起始地址、stride 和读取字段。用容量和对齐分析提出假设，还需合格事件或受控实验确认。
25. **为何不能声称 SoA 已向量化？** 实际 x86 编译报告没有跨行向量化，两条路径仍调用标量 libm。字段连续提供了可能性，实际代码形态才支持结论。
26. **8,192 行恰为 1 MiB，能否称为 L2 拐点？** 这只说明名义输入加一输出等于容量量级。还有原输入留存、活跃输出、访问地址、缓存组和并发活动。当前数据不能识别容量拐点。
27. **AMD L1D 两个 alias 代表什么？** 固定内核将它们映射为 data-cache accesses 和 miss 触发的 L2 请求。用户态进程树的两个计数之比保留这一定义。专用 LLC 尚无合格数据。
28. **瓶颈迁移能画成 100% 堆叠吗？** 图中 order handling 包含撮合、恢复等子区间。保留包含式时长和相同场景的匹配关系，图用同轴或分组并列。

### E｜验证、统计与复现

29. **为什么 E 的参考实现独立？** 独立 stock PAMS 进程直接调用固定 SequentialRunner 生成轨迹，没有执行生产 CoreOrder 的恢复和原生路径。观测与对照代码可审查。
30. **C01 和 V01 有何关系？** C01 检查系统支持范围和边界。V01 绑定正式条件的实际源码、扩展、主机、配置与 seed；成功回执同时指向独立参考及差分。
31. **正式数据如何准入？** 原 G3 需要 A/E 同锁真实签认，当前待签。已测的独立实验有组长批准，使用独立锁，仍逐条检查 V01、实际后端、环境、封印和市场工作量。
32. **为何三次重复不算三个独立市场？** 同一 seed 复用同一金融世界。先计算同区组 log-ratio，再在 seed 内按协议聚合，以 seed 为单位进行 10,000 次 bootstrap。
33. **超时或配对缺失怎么进统计？** 超时保留右删失，预热线保留台账。冻结规则要求的配对缺失时主估计缺测，逐次记录与合格计数仍报告。
34. **何时可用 PMU？** 实际事件与请求相符，采集退出正常，计数合法，运行时间为正，未缩放且覆盖至少 95%。合法零事件与事件缺失分开记录。
35. **现场通过与独立复现怎么区分？** 现场 Demo 由自动化在同一主机运行，已验证六候选与独立参考。由真实非模块作者在其自身环境重建、核对身份并回交原件后，才形成独立人员复现回执。
36. **能报告原版到最终组合的正式总加速吗？** 可以。W2-H 同区组的原版对四 worker AoS / SoA 分别为 13.266× / 13.143×，各基于 15 个有效配对。仅增量堆的直接效应是 16.704×。


### 跨模块追问

37. **为什么 heap-only 比完整配置更快？** 相同的增量堆已去掉大部分恢复成本；原生准备、绑定和四 worker 提交增加时间。W2-H 的 heap-only 在 15 个区组中全部用时最短。
38. **如何解释 100% PMU 运行覆盖率？** 在记录范围内事件运行时间占启用时间为 100%，且计数未缩放。手头没有一个专用 LLC 指标，也没有逐内核隔离的计数。
39. **Amdahl 敏感性用了什么范围？** 同一 W2-H direct AoS profile 的全绑定为 1.930047 ms，仪器化仿真为 4.346254 s。把前者压到四分之一且其余固定，模型给出 1.000333×。这个是局部介入的条件计算。
40. **25 项各 15 个配对能算作 375 个独立 seed 吗？** 多项对照共享运行，技术重复共享市场轨迹。每项比较只有五个独立的市场 seed。
41. **W2-H 为什么有两个不同的堆加速数字？** H01 堆专用对照为 16.956×，综合六配置的冻结区组为 16.704×。两项各自使用实际匹配区组。
42. **真实功能演示应秀哪一组时间？** Demo 用于展示确定性和可操作性。论文表展示华硕低开销的配对统计，两者计时口径不同。
